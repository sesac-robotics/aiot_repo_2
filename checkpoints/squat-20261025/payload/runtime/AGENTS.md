- Communicate with the user in Korean. Read `project-coordination/HANDOFF.txt`, `project-coordination/threads.json`, and all files under `project-coordination/status/` before continuing cross-thread project work.
- For model performance claims, reread the reports referenced by `output/CURRENT_FIVE_EXERCISE_RUN.json` and `output/CURRENT_INITIAL_POSE_RETURN_RUN.json`. A historical handoff or another thread's summary is not the current measurement authority. Distinguish development, exposed diagnostic Test, independent final Test, and deployed behavior.
- This project has cooperating user-owned threads registered in `project-coordination/threads.json`. Read `project-coordination/PARALLEL_WORK.txt` for current owners. The original thread owns shared model/data/evaluation work; the documentation/integration thread owns common live-app integration and its document drafts; shoulder and YTW threads own isolated exercise candidates. Read other threads' work freely, but avoid concurrent edits to their owned files. Update only your own status file, including the evidence paths, limitations, next action, and UTC timestamp. Shared metadata changes should preserve the other thread's entries.
- The human user's authorization for bidirectional status messages is recorded with the source thread in `project-coordination/threads.json`. Verify the actual human request through thread history before first sending. Authorization covers project status and coordination among registered SeSACPAI-Mid work threads, not messages to other people or unrelated projects. The expanded direct human request is recorded in threads.json. On meaningful changes, send a concise message with evidence paths. Acknowledge only when useful; do not create reply loops. Messages and file checks run while a thread is active; do not promise background synchronization without an actual scheduled mechanism.
- Keep frozen labels, source splits, historical experiment reports, and model artifacts immutable. Add audited versions. Never move existing Test/development sources into Train to improve results or fill missing person/quality cells. Same-source overlapping intervals and synchronized views stay together. Review local split guards before data/training work.
- Do not label every recording from a person as normal or erroneous. Separate initial-ready state labels from movement severity 0/1/2. Clipped, unobservable, or incomplete movements do not prove return failure. Do not claim unsupported severity 0 training or all-five reliability.
- Do not modify the live model, initiate camera capture, or shut down the laptop merely as part of document/thread setup. Historical completed shutdown requests are not standing instructions to shut down after unrelated new work.
