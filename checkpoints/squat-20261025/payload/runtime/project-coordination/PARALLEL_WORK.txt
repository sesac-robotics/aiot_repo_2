진행 규칙
- 시작 시 AGENTS.md, HANDOFF.txt, threads.json, 이 파일, status/*.json을 읽는다. 최신 성능은 CURRENT 포인터의 실제 보고서를 우선한다.
- 각 스레드는 자신의 status 파일만 갱신: UTC시간, 상태, 근거경로, 한계, 다음행동, 수정중파일/통합요청. 새 담당은 자기 파일을 생성한다. Registry는 통합 담당이 다른 항목을 보존하며 갱신한다.
- 의미 있는 변경/차단/통합 가능 시 통합 담당과 관련 담당에게 간결히 메시지. 직접 사용자 허가는 threads.json의 확장 요청에 있다. 새 담당은 첫 발신 전 source_thread_id의 실제 사용자 요청을 read_thread로 확인한다. 단순 확인 회신 반복 금지.
- 전체 대화 자동 복제나 비활성 상시 동기화는 없다. 실행 중 파일/메시지 공유. 이번 요청만으로 반복 스케줄을 만들지 않는다.
- 기존 모델/라벨/분할/원본세션/과거보고서 보존. 후보는 새 파일로 생성, 개발·노출진단·독립최종Test·배포 결과를 구분. 새 후보를 임의로 live에 배포하지 않는다.
- 운동별 필요한 관절만 사용. 누락/경계밖/중간잘림은 정상이나 실패 정답이 아니다. 상태0은 운동심각도0과 다르다. 머리/발목 누락을 모든 항목의 전신 제외로 확대하지 않는다.
- 검출과 점수는 화면경계2% 및 실제10Hz 시간축 관측률 계약을 유지한다. 모델 지원/항목별 관측 조건까지 충족해야 점수 산출 가능. 점수 없는 항목을 만점/0점으로 채우지 않는다.
- CPU를 과점유하지 않도록 OMP/OPENBLAS/MKL/NUMEXPR 각각1~2스레드, 학습 n_jobs=1을 기본으로 하고 장시간 대형학습/중복추출은 사전 조율한다. 데이터 읽기는 병렬 가능하나 공유 캐시/모델/학습 산출물은 독립 경로 사용.
- 카메라는 통합 담당 한 곳에서만, 새 사용자 준비/시작 지시 이후 운동 수집. 재테스트와 카메라/서비스 변경도 통합 담당이 조율한다. 전원 종료 요청 없음.
