# ESP32-CAM 실시간 자세 오류 테스트

## VS Code 실행

1. `run_esp32cam_live.py`를 열고 오른쪽 위 **Run Python File ▶**를 누릅니다. 시스템 Python으로 실행해도 기존 `/home/yoo/yolo` 환경으로 전환합니다.
2. 자동으로 열린 `http://127.0.0.1:8780/`에서 주소 `http://192.168.15.208:81/stream`을 확인합니다.
3. 운동을 선택하고 **실시간 시작**을 누릅니다. 운동 종목은 자동 인식하지 않으므로 직접 선택해야 합니다.
4. 한 사람의 필요한 관절이 보이도록 카메라를 놓고 약 5~7초 이상 움직입니다. 영상 옆에 오류 이름, 영어 교정 문구, 모델 점수가 표시됩니다.
5. 종목·주소를 바꾸려면 **중지** 후 변경하고 다시 시작합니다. **자세 다시 수집**은 현재 판정과 시간 구간을 초기화합니다.

F5의 **ESP32-CAM 실시간 자세 오류 테스트** 구성으로도 실행할 수 있습니다. 포트가 사용 중이면 기존 서버 터미널에서 Ctrl+C로 종료하거나 다음처럼 다른 포트를 지정합니다.

```bash
cd /home/yoo/R2D2/posture-error-training
python3 run_esp32cam_live.py --port 8781
```

## 처리 흐름과 모델

ESP32-CAM은 영상을 전송하고 PC가 OpenCV → MediaPipe 33개 관절 → 기존 전처리 → CNN/GRU 모델 추론을 수행합니다. ESP32 자체에서 신경망을 실행하지 않습니다. 선택된 모델은 스쿼트·푸시업·엘보 플랭크·YTW·숄더 프레스의 기존 `best.pt`입니다. YTW 영상과 학습 모델을 변경하지 않았습니다.

최신 프레임만 처리하며 약 6 FPS를 목표로 32개 표본을 모읍니다. 실제 속도는 카메라·PC에 따라 달라집니다. 오류 문구는 최근 3번 중 2번 이상 감지되고 현재도 감지된 항목만 표시합니다. 연결 재시도, 1초 이상 프레임 지연, 관절 누락, 해상도 비율 변경 시 이전 결과를 지웁니다. 관절 신뢰도가 잠깐 낮으면 최대 2개 표본을 허용하되 그 시점의 판정 문구는 숨깁니다.

## 결과 해석

- 모델 점수는 해당 오류의 출력이며, 보정된 정확도나 성능 지표가 아닙니다.
- 선택 오류 미검출은 전체 자세가 정상이라는 보장이 아닙니다.
- 숄더 프레스는 소량의 미검증 라벨로 학습한 실험 모델입니다. 실제 운동 교정의 신뢰도를 아직 보장할 수 없습니다.
- 다른 네 종목도 저장 영상 평가와 실제 ESP32-CAM 환경의 성능은 다를 수 있습니다. 현장 영상에 대한 별도 정답 평가가 필요합니다.
- 기존 YTW 데이터의 동작 형태를 그대로 사용합니다. 사용자가 다른 형태로 수행하면 분포 차이가 생길 수 있습니다.

## 연결·기록·확인

PC와 카메라가 같은 네트워크에서 통신 가능한지, 카메라 전원 및 스트림 서버가 켜져 있는지 확인합니다. 주소가 바뀌면 화면에서 수정할 수 있습니다. 연결 실패 시 상태 문구를 표시하고 재연결합니다. 중지 버튼은 카메라 처리도 종료합니다.

기본값은 영상과 판정 모두 저장하지 않습니다. **판정 로그 저장**을 켜고 시작하면 `live_sessions/*.jsonl`에 시각·종목·모델 결과만 저장합니다. 원본 영상은 저장하지 않습니다. 서버는 PC의 `127.0.0.1`에서만 열립니다.

저장 영상으로 같은 처리 경로를 검증할 수도 있습니다. 입력란에 절대 영상 경로를 넣으면 화면에 **저장 영상 재생 테스트**라고 구분하여 표시합니다. 영상이 반복되면 버퍼를 초기화하므로 32개 유효 표본을 모을 수 있는 충분한 길이의 영상을 사용하세요.

개발 확인: `test_live.py`의 세션 초기화·판정 안정화·HTTP 제어 7개 테스트 통과. 저장 영상에서 실제 관절 추출, 32개 표본 수집 및 학습 모델 예측을 확인했습니다. 기존 ESP32-CAM 주소는 확인 당시 접속 시간이 초과되어, 실제 카메라와 사람을 이용한 검증은 아직 완료되지 않았습니다.

```bash
/home/yoo/yolo/bin/python test_live.py
```

OpenCV 연결 제한 시간은 [공식 VideoCapture 속성 문서](https://docs.opencv.org/5.0/main_modules/videoio_flags_base.html)의 `CAP_PROP_OPEN_TIMEOUT_MSEC` 및 `CAP_PROP_READ_TIMEOUT_MSEC`를 사용합니다.

### 스트림 포트만 응답하지 않는 경우

카메라 웹 페이지와 `/capture`는 열리지만 `:81/stream`이 응답하지 않는 경우, 프로그램은 같은 카메라의 80번 포트 `/capture` 사진을 연속 수신하는 방식으로 자동 전환합니다. 화면에 **ESP32-CAM LIVE · 사진 연속 수신**이라고 표시합니다. 실제 수신 속도에 따라 32개 관절 수집에 8초 이상 걸릴 수 있습니다. 2026-10-21 실제 카메라에서 약 4 FPS 수신과 MediaPipe 처리까지 확인했습니다. 전신이 보이지 않는 상태여서 실제 운동 오류의 정확도는 검증하지 않았습니다.

### 교정 문구 위치

창이 좁아도 영상 바로 위에 현재 판정과 영어 교정 문구를 표시합니다. 중지하면 현재 판정은 종료하고, 마지막 유효 결과를 **중지 전 마지막 판정**이라고 구분하여 남깁니다. 새 테스트를 시작하면 이전 결과는 초기화됩니다. 관절 수집 중·관절 누락·선택 오류 미검출·오류 후보 재확인을 각각 구분합니다. 스쿼트 모델은 `shallow` 및 `back not straight` 두 가지 오류만 학습했으므로 다른 오류에 대한 문구는 나오지 않습니다.
